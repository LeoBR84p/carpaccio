Architecture decisions

Six choices. Each intentional.

Design rationale recorded at implementation time.

01

Bot on Iceland VPS, not GCP

Zero Google account linkage for the bot process. IP of outbound Telegram requests is the anon VPS, not GCP. Decouples Telegram identity from cloud billing identity.

02

HMAC shared secret via env var

All bot-to-runner and runner-to-delivery auth uses a shared HMAC secret. No GCP Secret Manager — that would tie secrets to a Google account. Secret lives only as env vars on VPS and Cloud Run.

03

Payment after download

Job runs first. Stars invoice is issued only when the file is ready and a link exists. If the job fails, no Stars are charged. User contacts support for any edge-case refund.

04

Inline keyboard for quality

Buttons instead of typed numbers. UX: tap to select format, no FSM ambiguity from free-text replies. Eliminates the class of bugs where a digit reply is misrouted to the wrong state.

05

Synchronous Cloud Run request

Runner processes within the HTTP request (up to 30 min). Bot fires the request async via create_task, no await. Cloud Run max timeout is 3600s, keeping the architecture simple with no job queue.

06

Streaming delete on serve

Delivery server uses an async generator that deletes the file after the last byte is yielded. Token is removed from memory on first access, before streaming begins. One-time guarantee is enforced at two layers.

Components built

Three services. One flow.

Each component is self-contained with its own Dockerfile, requirements, and env vars.

Bot

bot/

aiogram 3, webhook mode, MemoryStorage FSM, aiohttp web server hosting /telegram + /callback endpoints. Manages quality selection via inline keyboard and issues Stars invoice only after job completion.

  • main.py
  • states.py
  • pricing.py
  • probe.py
  • requirements.txt
  • Dockerfile
  • .env.example

Runner

runner/

FastAPI, yt-dlp + ffmpeg download, paramiko SFTP upload to VPS, HMAC-signed callback to bot on completion. Runs entirely within the HTTP request lifecycle — no async queue, no persistent state.

  • main.py
  • requirements.txt
  • Dockerfile
  • .env.example

Delivery

delivery/

FastAPI streaming response with post-stream delete, 1-hour token expiry fallback, nginx with access_log off. Token is popped from the in-memory dict on the first request, before any bytes are sent.

  • server.py
  • nginx.conf
  • requirements.txt
  • Dockerfile
  • .env.example

Six steps to live.

All code is ready. These are operator actions required before first run.

P1

GCP Cloud Run service

Deploy runner image, set env vars, configure timeout 3600s, set min-instances=0. Requires Google Cloud account and billing enabled.

Operator action
P2

VPS setup

Provision Iceland VPS (1984.is or OrangeWebsite), pay with Monero, install nginx, Python 3.12, certbot. Copy deployment files and start services.

Operator action
P3

Domain + TLS

Point domain to VPS IP, run certbot, validate Let's Encrypt certificate. Update BOT_DOMAIN and DELIVERY_DOMAIN env vars across all components.

Operator action
P4

Telegram bot

Create via @BotFather, enable Stars payments, set webhook to https://vps-domain/telegram. Copy bot token into BOT_TOKEN env var.

Operator action
P5

SFTP key pair

Generate RSA key pair, copy public key to VPS authorized_keys, paste private key into runner SFTP_PRIVATE_KEY env var. Test upload path before deploying runner.

Operator action
P6

Secrets generation

Generate three secrets with openssl rand -hex 32 for BOT_RUNNER_SECRET, RUNNER_DELIVERY_SECRET, and DELIVERY_TOKEN_SALT. Never reuse across environments.

Operator action

Privacy invariants

What was built vs. what is deploy-time.

    Zero URL logs

    yt-dlp invoked with --quiet, no payload written to stdout or log files. URL never persisted beyond in-memory variable lifetime.

    Implemented in code

    Zero Telegram ID persistence

    Only in-memory Python dicts hold the mapping from chat_id to job state. No database write, no file write, no log write. Cleared on process restart.

    Implemented in code

    Zero access logs

    access_log off; is present in delivery/nginx.conf. No HTTP access log file will be created on the delivery VPS.

    Implemented in code

    Token one-time

    Token is popped from the in-memory dict on first GET /file/{token} before streaming begins. File is deleted via async generator after last byte yielded. Two-layer guarantee.

    Implemented in code

    VPS anonymity

    Provider choice (1984.is or OrangeWebsite) and Monero payment are operator decisions at provisioning time. Cannot be verified until VPS is created.

    Pending deploy

    Cloud Run no-disk persistence

    Configure with --no-allow-unauthenticated set correctly and verify ephemeral /tmp behavior. Cloud Run instances do not persist storage between requests by default — confirm at deploy time.
